# チュートリアル：はじめての 1 冊を KDP で出版する

このテンプレートを初めて使う人が、**原稿を書き始めてから Kindle ストアで販売されるまで**を、順番どおりに進めるための手順書です。

- 各機能の詳しい説明は [README](../README.md) にあります。このチュートリアルでは「何を、どの順番でやればよいか」に絞って説明し、詳しい内容は README の該当箇所へリンクします
- コマンドは macOS / Linux / WSL を前提にしています。Windows（WSL を使わない場合）の読み替えは [付録：Windows で進める場合](#付録windows-で進める場合) を参照してください
- 例として、横書きの本を `books/my-book` というフォルダで作ります。名前は自由に変えてかまいません

## 0. 全体の流れ

| 段階 | やること | 使うもの | 主な成果物 |
|:--|:--|:--|:--|
| 準備 | テンプレートの取得、ツールのインストール | `scripts/setup.sh` | ビルドできる環境 |
| 執筆 | 本のフォルダを作り、`book.yaml` と原稿を書く | テキストエディタ | `books/my-book/` |
| 仕上げ | 表紙の用意、原稿のチェック、ビルド、検証 | `npm run lint`、`scripts/build.py` | `dist/my-book.epub`、表紙画像 |
| 確認 | Kindle での見た目を確認 | Kindle Previewer 3 | 問題のない EPUB |
| 出版 | KDP に情報を入力し、EPUB と表紙をアップロード | KDP の本棚 | 販売ページ |

最初は「サンプルをそのままビルドできること」を確認し、それから自分の本に書き換えていくと、問題が起きたときに原因を切り分けやすくなります。

## 1. 準備するもの

### パソコンとツール

| もの | 必須か | 用途 |
|:--|:--:|:--|
| macOS / Linux / Windows（WSL 推奨）のパソコン | ○ | ビルドの実行 |
| テキストエディタ（VS Code など） | ○ | 原稿と設定ファイルを書く |
| Git | 推奨 | テンプレートの取得、原稿の履歴管理 |
| Pandoc 3.1 以上、Python 3.9 以上 | ○ | EPUB の生成（手順 3 で入れる） |
| Java 11 以上 + EPUBCheck | 推奨 | EPUB の検証（手順 3 で入れる） |
| Node.js 20 以上 | 推奨 | 原稿のチェック（手順 3 で入れる） |
| Kindle Previewer 3 | 推奨 | Kindle での見え方の確認（手順 10 で入れる） |

### KDP のアカウント

[KDP（Kindle ダイレクト・パブリッシング）](https://kdp.amazon.co.jp/) のアカウントを作り、次の情報を登録しておきます。登録には時間がかかることがあるので、**執筆と並行して早めに済ませておく**のがおすすめです。

- 著者（出版者）情報
- 支払い情報（ロイヤリティを受け取る銀行口座）
- 税務情報（画面の質問に答えて登録する）

### 先に決めておくとよいこと

- **縦書きか横書きか**：小説・エッセイ・一般の実用書は縦書き、コードや英数字が多い技術書は横書きが一般的です。あとから `book.yaml` の 1 行で切り替えられるので、迷ったら横書きで始めてもかまいません
- **書名・著者名の表記**：EPUB・表紙・KDP の入力欄で同じ表記にする必要があります。早めに決めておくと手戻りが減ります

## 3. ツールをインストールして動作を確認する

### 3-1. ビルド用のツールを入れる

```bash
bash scripts/setup.sh
```

Pandoc、Python のパッケージ（PyYAML・Pillow）、EPUBCheck がまとめて入ります。Java が無い場合はインストール方法が表示されるので、その案内に従って Java 11 以上を入れてから、もう一度 `bash scripts/setup.sh` を実行してください。詳しくは README の [セットアップ](../README.md#セットアップ) を参照してください。

Linux / WSL で表紙を自動生成する場合は、日本語フォントも入れておきます（macOS は不要）。

```bash
sudo apt install fonts-noto-cjk
```

### 3-2. 原稿チェック用のツールを入れる

[Node.js](https://nodejs.org/) 20 以上を入れてから、次を実行します。

```bash
npm install
```

### 3-3. サンプルがビルドできるか確かめる

```bash
make check
```

最後に次のような表示が出て、`dist/` に `horizontal-sample.epub` と `vertical-sample.epub` ができれば準備完了です。

```text
[epubcheck]   EPUBCheck 5.3.0・EPUB 3.3: 0 fatal / 0 error / 0 warning / 0 info / 0 usage
[epubcheck]   ✓ 問題ありません
```

ここで一度、できた EPUB を Kindle Previewer（手順 10）や手持ちの EPUB リーダーで開き、サンプルの原稿（`books/horizontal-sample/chapters/`）と見比べておくと、どう書けばどう表示されるかのイメージがつかめます。

> エラーになった場合は、README の [トラブルシューティング](../README.md#トラブルシューティング) を確認してください。この段階のエラーはツールのインストールの問題なので、自分の原稿を書き始める前に解決しておきます。

## 4. 自分の本のフォルダを作る

サンプルをコピーして、自分の本のフォルダを作ります。

```bash
# 横書きの本
cp -r books/horizontal-sample books/my-book

# 縦書きの本（こちらを使う場合は上の行の代わりに）
cp -r books/vertical-sample books/my-book
```

- フォルダ名（`my-book`）は、出力される EPUB のファイル名（`dist/my-book.epub`）になります。**半角英数字とハイフン**にしておくと安全です
- 縦書きサンプルには `textlint.json`（漢数字を許可する、縦書き向けのチェック設定）が入っています。縦書きの本ではそのまま残してください

次に、この本だけの識別子（UUID）を作ります。

```bash
python3 -c "import uuid; print(uuid.uuid4())"
```

表示された値（`0b6a4d2c-9a51-4a8e-...` のような文字列）を控えておきます。次の手順で `book.yaml` に書きます。

> **重要**：**UUID はコピー元のサンプルの値のままにせず、必ず新しい値にしてください。** また、一度出版したら**変えないでください**（改訂版も同じ本として扱われるようにするため）。

## 5. book.yaml に本の情報を書く

`books/my-book/book.yaml` を開き、書誌情報を自分の本に書き換えます。コメント（`#` から行末まで）は残しておいてもかまいません。

まず書き換えるのは次の項目です。

```yaml
title: はじめての小さな本                  # 書名
title_kana: ハジメテノチイサナホン          # 書名の読み（並べ替え用。省略可）
subtitle: テンプレートで1冊出版する         # 副題（無ければ行ごと削除）
author:
  - name: 川田 太郎                        # 著者名
    kana: カワダ タロウ                    # 読み（省略可）
publisher: 川田 太郎                       # 個人出版なら著者名やレーベル名（省略可）
language: ja
date: 2026-12-01                          # 出版日（YYYY-MM-DD）
description: >-
  本の内容紹介を 1〜3 文程度で書きます。
keywords: [キーワード1, キーワード2]
rights: © 2026 川田 太郎

isbn: ""                                  # KDP の電子書籍は ISBN 不要。空のままで OK
uuid: ここに手順 4 で作った値を貼り付ける

chapters:                                 # 原稿の順番（手順 6 で書き換える）
  - chapters/00-preface.md
  - chapters/01-first.md

layout:
  writing_mode: horizontal                # horizontal = 横書き / vertical = 縦書き
```

- `title` と `author` の `name` は、**表紙と KDP の入力欄でも同じ表記**にします（手順 11）
- `layout` の残りの項目（章番号の書式など）は、サンプルの値のままで問題ありません
- すべての項目の意味は README の [設定ファイル book.yaml](../README.md#設定ファイル-bookyaml) にあります

## 6. 原稿を書く

### 6-1. サンプルの原稿を片付ける

`books/my-book/chapters/` にはサンプルの原稿が入っています。参考にしたい場合は残しておき、自分の原稿ができたら削除します。`book.yaml` の `chapters` に書いたファイルだけが本に入るので、残っていてもビルドには影響しません。

`books/my-book/images/` のサンプル画像も、使わないものは削除してかまいません。

### 6-2. 章ごとにファイルを作る

**1 章 = 1 ファイル**で、ファイルの先頭に `# 章タイトル` を 1 つだけ書きます。ファイル名に番号を付けると並び順がわかりやすくなります。

`books/my-book/chapters/00-preface.md`：

```markdown
# はじめに {.unnumbered}

この本を手に取っていただき、ありがとうございます。
```

`books/my-book/chapters/01-first.md`：

```markdown
# 最初の章 {#sec:first}

本文を書きます。段落と段落の間は空行で区切ります。

## 節の見出し

**太字**で強調したり、脚注を付けたりできます[^1]。

[^1]: 脚注の内容です。Kindle では番号をタップするとポップアップで表示されます。
```

- `{.unnumbered}` を付けた章は章番号が付きません（まえがき・あとがき向け）。付けない章は「第1章」「第2章」…と自動で番号が付きます
- 章を追加したら、`book.yaml` の `chapters` にも**読ませたい順番どおりに**追加します
- 目次は見出しから自動で作られるので、自分で書く必要はありません

### 6-3. 画像を入れる

画像ファイルを `books/my-book/images/` に置き、原稿から参照します。

```markdown
![作業の流れ](images/flow.png){#fig:flow}
```

- キャプション（`[ ]` の中）を書くと「図1.1」のような番号が付きます
- 写真は JPEG、図は PNG を使い、幅 1,200px 以上を目安にします。大きすぎる画像や透過 PNG は、ビルド時に Kindle 向けに[自動で調整](../README.md#画像の最適化)されます（元の画像は変更されません）

### 6-4. 使える書き方

コードブロック・表・注意書きの囲み・ルビ・相互参照なども使えます。書き方は README の [原稿の書き方](../README.md#原稿の書き方) と、サンプル原稿 `books/horizontal-sample/chapters/01-writing.md`（すべての記法の実例）を参照してください。

### 6-5. 書きながらこまめにビルドする

数章書いたら、途中でもビルドして見た目を確認しましょう。最後にまとめて確認するより、問題の原因を見つけやすくなります。

```bash
make book BOOK=books/my-book
```

`dist/my-book.epub` ができます。

## 7. 表紙を用意する

KDP では、表紙画像を **EPUB とは別に** アップロードします。表紙の用意のしかたは 2 通りあります。

| 方法 | 向いている人 | 設定 |
|:--|:--|:--|
| A. 自動生成する | まず 1 冊出してみたい人、文字だけのシンプルな表紙でよい人 | `cover_design` を書く |
| B. 自分で作った画像を使う | デザインツールやデザイナーに依頼して表紙を作る人 | `cover` に画像のパスを書く |

### A. 自動生成する

`book.yaml` に次の 1 行を加えます（サンプルの `cover_design` のコメントを外してもかまいません）。

```yaml
cover_design: {}
```

ビルドすると、書名・副題・著者名から KDP の推奨サイズ（1600×2560px の JPEG）の表紙が作られ、`dist/my-book-cover.jpg` に保存されます。同じ画像が EPUB にも自動で埋め込まれます。

色・フォント・背景画像・改行位置などは変更できます。詳しくは README の [表紙の自動生成](../README.md#表紙の自動生成) を参照してください。表紙だけを作り直して確認したいときは、次のコマンドが便利です。

```bash
python3 scripts/cover.py books/my-book    # → dist/my-book-cover.jpg
```

### B. 自分で作った画像を使う

次の条件で画像を作り、`books/my-book/images/cover.jpg` を差し替えます（`cover_design` は書かないでください。書いてあると自動生成が優先されます）。

- 大きさ：**幅 1600 × 高さ 2560 px**（縦横比 1:1.6）
- 形式：JPEG、色は RGB（CMYK は不可）
- 書名・著者名は `book.yaml` と同じ表記にする
- サムネイル（小さい表示）でも書名が読める大きさにする

```yaml
cover: images/cover.jpg
```

KDP の表紙の要件は変わることがあるので、作る前に [電子書籍の表紙の作成（KDP ヘルプ）](https://kdp.amazon.co.jp/ja_JP/help/topic/G6GTK3T3NUHKLEFX) で最新の値を確認してください。

> フォントや背景画像、イラストを使う場合は、**商用の電子書籍の表紙に使えるライセンスか**を必ず確認してください。

## 8. 原稿をチェックする

原稿を書き終えたら、表記ゆれ・文章の誤り・リンク切れ・参照ミスをまとめてチェックします。

```bash
npm run lint -- books/my-book
```

```text
📖 my-book（横書き・原稿 2 ファイル）
  表記・文章     ✔ 問題なし
  リンク・参照   ✔ 問題なし  外部 URL 0 件
```

指摘が出た場合：

- **✖ エラー**：直します。「自動修正可」と書かれたもの（表記の統一など）は、次のコマンドでまとめて直せます。

  ```bash
  npm run lint:fix -- books/my-book
  ```

- **⚠ 警告**：文が長い、同じ助詞が続くなどの文体の提案です。読み直して、直すかどうかを自分で判断します

誤検出を抑える方法や、本で使う用語のルールを追加する方法は、README の [原稿のチェック](../README.md#原稿のチェック) を参照してください。

> チェックツールは誤字・脱字のすべてを見つけられるわけではありません。**最後は必ず自分の目で通読**し、できればほかの人にも読んでもらいましょう。

## 9. EPUB をビルドして検証する

KDP にアップロードする EPUB を作り、EPUBCheck で規格に合っているかを検証します。

```bash
python3 scripts/build.py books/my-book --check
```

次のように表示されれば成功です。

```text
[build] 出力: dist/my-book.epub
[epubcheck] 検証: dist/my-book.epub
[epubcheck]   EPUBCheck 5.3.0・EPUB 3.3: 0 fatal / 0 error / 0 warning / 0 info / 0 usage
[epubcheck]   ✓ 問題ありません
```

このテンプレートは、エラーだけでなく**警告が 1 件でもあれば失敗**にします。失敗したときは、表示された場所（EPUB 内のファイル・行）とメッセージを手がかりに原稿や `book.yaml` を直します。よくある原因は README の [トラブルシューティング](../README.md#トラブルシューティング) にまとめてあります。

ビルド中に `[build]` の行で警告（表紙のサイズが推奨と違う、参照先が見つからない、画像が小さいなど）が出た場合も、出版前に直しておきましょう。

### サンプルを削除する

自分の本ができたら、サンプルは削除してかまいません。削除すると、`make` や `make check` で自分の本だけがビルドされるようになります。

```bash
rm -rf books/horizontal-sample books/vertical-sample
```

> GitHub を使っている場合は、ここで commit・push しておきましょう。GitHub Actions でもビルドと検証が行われ、「Actions」タブの「Artifacts」から EPUB をダウンロードできます。

## 10. Kindle Previewer で見た目を確認する

EPUBCheck が調べるのは EPUB の規格に合っているかどうかだけで、**Kindle でどう見えるかは調べません**。KDP にアップロードする前に、Amazon 公式の [Kindle Previewer 3](https://kdp.amazon.co.jp/ja_JP/help/topic/G202131170)（Windows / macOS、無料）で確認します。

1. Kindle Previewer 3 をダウンロードしてインストールする
2. 起動して `dist/my-book.epub` を開く（ドラッグ＆ドロップでも可）。変換に数十秒かかる
3. デバイスの種類を **タブレット / 電話 / Kindle E-reader** に切り替えて、それぞれで確認する
4. 画面の向きや文字の大きさを変えて、崩れないか確認する

最低限、次の点を確認してください。

- [ ] 表紙が表示される
- [ ] 目次から各章へ移動できる
- [ ] ページが正しい方向に進む（**縦書きは右から左**、横書きは左から右）
- [ ] 画像・表・コードが画面からはみ出したり、途中で切れたりしていない
- [ ] 脚注の番号をタップするとポップアップが出る
- [ ] E-reader（白黒）表示やダークモードでも文字・図が読める

確認する項目の全体と、縦書きの本で特に注意する点は、README の [Kindle Previewer での確認方法](../README.md#kindle-previewer-での確認方法) にあります。

問題が見つかったら、原稿を直して手順 8〜10 をくり返します。

## 11. KDP に入力する情報を準備する

KDP の登録画面では、EPUB のほかに多くの情報を入力します。画面を開いてから考えると時間がかかるので、次の表を埋めておくとスムーズです。

| 項目 | 内容 | メモ |
|:--|:--|:--|
| 言語 | 日本語 | |
| 本のタイトル | `book.yaml` の `title` と**同じ表記** | |
| タイトルのフリガナ・ローマ字 | 日本語の本では入力が必要 | |
| サブタイトル（あれば）とフリガナ・ローマ字 | `book.yaml` の `subtitle` と同じ表記 | |
| 著者名とフリガナ・ローマ字 | `book.yaml` の `author` と**同じ表記** | |
| 内容紹介 | 販売ページに表示される紹介文。`book.yaml` の `description` より詳しく書いてよい | 読者が「読みたい」と思える内容に |
| キーワード | 最大 7 個。読者が検索しそうな語 | |
| カテゴリー | 本の内容に合う分類を画面の案内に従って選ぶ | |
| 出版に関して必要な権利 | 自分で書いた本なら「著作権を所有している」を選ぶ | |
| AI 生成コンテンツ | 文章・画像・翻訳に AI 生成のものを使ったか | 正直に回答する |
| アップロードするファイル | `dist/my-book.epub` | |
| 表紙画像 | 自動生成なら `dist/my-book-cover.jpg`、自作なら `books/my-book/images/cover.jpg` | |
| ISBN | **入力不要**（KDP が ASIN を割り当てる） | |
| DRM（デジタル著作権管理） | 有効にするかどうか。**出版後は変更できない**ので注意 | |
| KDP セレクト | 登録するかどうか（Kindle Unlimited の対象になる代わりに、電子書籍を Amazon 独占で販売する） | |
| ロイヤリティ | 35% か 70%。70% は価格の範囲などに条件がある | |
| 販売価格 | 日本（Amazon.co.jp）の価格。ほかの国の価格は自動で計算させることもできる | |

各項目の最新の条件（ロイヤリティの価格範囲、カテゴリーの数など）は、KDP の画面とヘルプで確認してください。

## 12. KDP にアップロードして出版する

[KDP](https://kdp.amazon.co.jp/) にサインインし、手順 11 で準備した内容を入力します。

### 12-1. 本を作成する

**本棚** で「＋ 電子書籍または有料マンガを作成」→「電子書籍」を選びます。

### 12-2. 電子書籍の詳細

言語、タイトル・サブタイトル（フリガナ・ローマ字）、著者、内容紹介、出版に関して必要な権利、キーワード、カテゴリーを入力し、「保存して続行」を押します。

### 12-3. 電子書籍のコンテンツ

1. **原稿**：DRM の有無を選び、「電子書籍の原稿をアップロード」で `dist/my-book.epub` を選ぶ
2. **表紙**：「表紙をアップロード」で表紙画像を選ぶ（EPUB に埋め込んだものと同じ画像）
3. **AI 生成コンテンツ**：質問に回答する
4. **プレビュー**：「プレビューアーを起動」で表示を確認する。縦書きの本は右綴じになっているかも確認する
5. **ISBN**：空欄のままでかまいません

アップロード後に KDP の画面でエラーや警告が表示された場合は、内容を確認し、原稿を直して再ビルドした EPUB をアップロードし直します。

### 12-4. 価格設定

KDP セレクトへの登録、出版地域（通常は「すべての地域」）、ロイヤリティプラン、販売価格を決めます。

### 12-5. 出版する

最後に「Kindle 本を出版」を押します。審査を経て、**通常 72 時間以内**に販売が始まります。審査の状況は本棚で確認でき、結果はメールでも届きます。

> 審査で修正を求められた場合は、メールの内容に従って原稿や登録情報を直し、もう一度出版の手続きをします。タイトル・著者名の表記が EPUB・表紙・入力欄で食い違っていると修正を求められやすいので、手順 11 の表で確認しておきましょう。

---

## 13. 出版したあと

### 販売ページを確認する

販売が始まったら、Amazon の販売ページで表紙・タイトル・内容紹介が正しく表示されているか確認します。実際に購入（または Kindle Unlimited で読む）して、Kindle 端末やアプリで最後まで表示を確かめておくと安心です。

### 誤字を直す・改訂版を出す

1. 原稿を直す
2. 手順 8〜10 をくり返す（チェック → ビルドと検証 → Kindle Previewer で確認）
3. KDP の本棚から「電子書籍のコンテンツを編集」を選び、新しい EPUB をアップロードして出版し直す

**`book.yaml` の `uuid` は変えないでください。** 同じ本の改訂として扱われるようにするためです。改訂の内容は `date` や「あとがき」などに書いておくと、読者にもわかりやすくなります。

### 2 冊目を作る

手順 4 から同じように進めます。`books/` の下に本のフォルダを増やせば、1 つのリポジトリで何冊でも管理できます（UUID は本ごとに新しく作ります）。
