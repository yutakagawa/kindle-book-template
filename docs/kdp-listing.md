# KDP の登録情報の下書きを作る（scripts/kdp-listing.py）

KDP で本を登録するときは、EPUB と表紙のほかに **内容紹介**・**キーワード（7 つ）**・**カテゴリー** を入力します。
`scripts/kdp-listing.py` は、原稿（`chapters/*.md`）と `book.yaml` から、この 3 つの**下書き**を 1 つの Markdown ファイルに書き出します。
あわせて、KDP の文字数・個数の制限や禁止事項に反していないかも確認します。

> 出力はあくまで下書きです。内容紹介は自分の言葉で書き直し、キーワードとカテゴリーは本の内容に合うかを確かめてから入力してください。

## 使い方

必要なのは Python 3 と PyYAML だけです（`pip install -r requirements.txt`。pandoc は不要）。

```bash
make listing                                   # books/ 以下の全ての本 → dist/<名前>-listing.md
```

```bash
make listing-book BOOK=books/my-book           # 1 冊だけ
```

スクリプトを直接実行することもできます。

```bash
python3 scripts/kdp-listing.py books/my-book            # → dist/my-book-listing.md
python3 scripts/kdp-listing.py --all                    # books/ 以下を全部
python3 scripts/kdp-listing.py books/my-book --stdout   # ファイルに書かずに画面に出す
python3 scripts/kdp-listing.py books/my-book --json     # dist/my-book-listing.json も書き出す
python3 scripts/kdp-listing.py books/my-book --check    # 制限やルールに反する項目があれば終了コード 1
python3 scripts/kdp-listing.py books/my-book -o out     # 出力先のディレクトリを変える
```

| オプション | 内容 |
|:--|:--|
| `--all` | `books/*/book.yaml` がある全ての本 |
| `-o`, `--output-dir` | 出力先（既定: `dist`） |
| `--stdout` | ファイルを作らず、標準出力に Markdown（`--json` と一緒なら JSON）を出す |
| `--json` | Markdown に加えて `<名前>-listing.json` を書き出す（ほかのツールで使うとき） |
| `--check` | 「要修正」の項目が 1 つでもあれば終了コード 1（CI や出版前の確認に） |

`dist/` は Git の管理対象外です。下書きを仕上げたら、`book.yaml` の [`listing`](#bookyaml-の-listing-で調整する) に書き写しておくと、次回からも同じ内容で確認できます。

## 出力の内容

`dist/<名前>-listing.md` には、次の内容がこの順番で入ります。

| 見出し | 内容 |
|:--|:--|
| タイトル・著者（確認用） | `book.yaml` の `title` / `subtitle` / `author` と文字数。KDP の入力欄・EPUB・表紙で表記をそろえるための確認用 |
| 内容紹介 | KDP の「内容紹介」欄にそのまま貼り付けられる HTML と、タグを除いた表示イメージ。文字数（`484 / 4,000 文字` のように）と、ルールのチェック結果 |
| キーワード | 7 つの入力欄に入れる候補を、欄ごとに文字数と由来（`book.yaml` か原稿か）つきで表にしたもの。入れ替え用の「その他の候補」と、候補から外した語とその理由 |
| カテゴリー候補 | 原稿に出てくる語から推定したカテゴリーを、当てはまりのよい順に最大 6 つ（上位 3 つは太字）。根拠になった語つき |
| チェック結果 | 「要修正」（KDP の制限・ルールに反している）と「参考」（キーワードが 7 個に足りない、など） |

出力の例（横書きサンプル `books/horizontal-sample` のキーワード）:

```text
| 欄 | キーワード | 文字数 | 由来 |
|--:|:--|--:|:--|
| 1 | EPUB | 4 | book.yaml の keywords |
| 2 | Pandoc | 6 | book.yaml の keywords |
| 3 | アップロード | 6 | 原稿から抽出 |
...
候補から外した語:
- Kindle … タイトル・サブタイトル・著者名などに含まれている（検索対象になるので不要）
```

## book.yaml の listing で調整する

`book.yaml` に `listing` を書くと、下書きの作り方を調整できます。すべて省略できます。

```yaml
listing:
  description: |                 # 内容紹介を自分で書いたら、ここに HTML で書く
    <p>毎日の「五分の作業」を、短いスクリプトで手放すための本です。</p>
    <h4>本書の内容</h4>
    <ul>
      <li>作業を観察して、自動化できるところを見つける</li>
      <li>はじめての Python スクリプトでファイルを一括リネーム</li>
    </ul>
  keywords: [時間管理, 業務改善]    # 必ず入れたいキーワード（7 個まで。上から順に欄 1, 2, … に入る）
  exclude_keywords: [ファイル]      # 原稿から抽出された候補のうち、使わない語
  categories:                    # KDP の画面で選んだカテゴリーのメモ（3 つまで）
    - コンピュータ・IT > プログラミング
    - ビジネス・経済 > 仕事術・整理術
```

| キー | 内容 |
|:--|:--|
| `listing.description` | 手で書いた内容紹介（HTML）。書くと自動の下書きは作らず、この文章の文字数・タグ・禁止事項だけを確認する |
| `listing.keywords` | 必ず使うキーワード。タイトルと重なっていても採用する（ガイドラインで禁止されている語と 50 文字超えは除外） |
| `exclude_keywords` | 候補にしない語（`listing.exclude_keywords`） |
| `listing.categories` | 決めたカテゴリーのメモ。出力の先頭に表示し、4 つ以上なら「要修正」にする |

キーワードは「`listing.keywords` → `book.yaml` の `keywords` → 原稿から抽出した語」の順に 7 つまで選びます。`book.yaml` の `keywords` は EPUB のメタデータ（`dc:subject`）にもなるので、両方に効く語はそちらに書くとよいでしょう。

## KDP の制限とルール（スクリプトが確認していること）

| 項目 | 制限・ルール | スクリプトの扱い |
|:--|:--|:--|
| 内容紹介の文字数 | **4,000 文字以内**（HTML タグも文字数に含む） | 自動の下書きは 4,000 文字に収まるよう、章の要約 → まえがきの段落 → 章の一覧の順に削る。手で書いたものは超えたら「要修正」 |
| 内容紹介の HTML | 使えるのは `<p>` `<br>` `<b>` `<em>` `<i>` `<u>` `<h4>` `<h5>` `<h6>` `<ol>` `<ul>` `<li>` のみ | それ以外のタグがあれば「要修正」。下書きは `<p>` `<h4>` `<ul>` `<li>` `<b>` `<br>` だけを使う |
| 内容紹介に書けないこと | URL・メールアドレス・電話番号などの連絡先、宣伝文句（「ベストセラー」「No.1」）、一時的な情報（「セール中」「今だけ」「無料」）、Amazon のプログラム名（「Kindle Unlimited」「KDP セレクト」） | 見つかれば「要修正」 |
| キーワードの数 | **最大 7 個**（7 つの入力欄） | 7 個まで選び、残りは「その他の候補」に回す |
| キーワードの長さ | **1 欄あたり 50 文字以内**。1 つの欄に複数の語を空白区切りで入れてもよい | 50 文字を超える語は除外 |
| キーワードに入れないもの | タイトル・著者名など**ほかの欄に入れた情報**、主観的な評価（「最高」「おすすめ」）、一時的な情報（「新刊」「セール」）、ほとんどの商品に当てはまる語（「本」「電子書籍」）、Amazon のプログラム名、ほかの著者名・作品名 | タイトル・サブタイトル・著者名・出版社名に含まれる語と、禁止語の一覧にある語は除外し、理由を表示する（ほかの著者名・作品名は判定できないので自分で確認する） |
| カテゴリーの数 | **最大 3 つ**（電子書籍・ペーパーバックなどの形式ごと） | 上位 3 つを太字で示す。`listing.categories` が 4 つ以上なら「要修正」 |
| タイトル | タイトルとサブタイトルを合わせて **200 文字未満**。タイトルに宣伝文句を入れない | 超えていたり、禁止語が入っていたりすれば「要修正」 |

> **根拠と注意**: 上の値は KDP ヘルプの「内容紹介」「キーワードを選択」「カテゴリーを選択」「メタデータのガイドライン」の内容にもとづいています。このスクリプトを作成した環境からは kdp.amazon.co.jp / kdp.amazon.com に直接接続できなかったため、検索で確認できた公開情報（内容紹介は HTML タグを含めて 4,000 文字、キーワードは 7 欄 × 50 文字、カテゴリーは 2023 年の変更以降 3 つまで）と、既知のヘルプの内容で値を決めています。KDP の仕様は変わることがあるので、登録の前に [KDP ヘルプ](https://kdp.amazon.co.jp/ja_JP/help) で最新の条件を確認してください。値を変えるときは `scripts/kdp-listing.py` の先頭にある定数（`DESCRIPTION_MAX` `KEYWORD_SLOTS` `KEYWORD_MAX` `CATEGORY_MAX` `TITLE_MAX` `ALLOWED_TAGS` `PROHIBITED_TERMS`）を書き換えます。

## 下書きの作り方（仕組み）

### 内容紹介

1. `book.yaml` の `description` を最初の段落にする
2. まえがき（本文の章より前にある、`{.unnumbered}` の章）の段落を最大 3 つ続ける
3. 「本書の内容」として、章ごとに「`第1章　章タイトル`」と、その章の最初の段落の 1 文目を箇条書きにする（章番号は `layout.chapter_label` / `appendix_label` に合わせる）

原稿の Markdown は読める文章に直してから使います（ルビは親文字だけ、強調・リンクは文字だけにする）。インラインコード・相互参照（`[@sec:…]`）・URL を含む段落、箇条書き、コードブロック、表、脚注は、文章が途中で切れてしまうので内容紹介には使いません。「サンプル」「テンプレート」という語を含むまえがきの段落も除きます。

### キーワード

原稿の章タイトル・見出し・本文から、カタカナ語・英単語（`Kindle Previewer` のような複数語も含む）・漢字の熟語を拾って数えます。見出しに出てくる語は重く数え、複数の章に出てくる語を優先します。1 回しか出てこない語、「本書」「場合」「方法」のような文章によく出るだけの語、漢字 2 文字の一般的な語は候補になりにくくしています。形態素解析は使っていないので、語の切れ目がずれることがあります。

### カテゴリー

スクリプトの中の表（`CATEGORY_TABLE`）に、Kindle ストアの分類をもとにしたカテゴリーの目安と、判定に使う語（「プログラミング」「Python」「自動化」「仕事術」など）を登録しています。タイトル・`description`・キーワード（5 倍）、見出し（3 倍）、本文（1 倍）にその語が出てくる回数で点数を付け、点数の高い順に並べます。

KDP のカテゴリーは、登録画面の「カテゴリーを選択」で、Amazon のストアの分類から選びます。表の名前は目安なので、**画面で同じか近い名前のものを選んでください**。自分の分野がうまく判定されないときは、`CATEGORY_TABLE` に行を足すか、判定に使う語を増やします。

## 下書きを仕上げるときのコツ

- **内容紹介**: 冒頭の 2〜3 行が、販売ページで「もっと読む」を押さずに見える部分です。「誰の」「どんな悩みを」「どう解決する本か」をそこで伝え、章の一覧は後ろに置きます。対象読者（「こんな方におすすめ」）や、読んで得られることを `<h4>` の見出しつきで足すと読みやすくなります
- **キーワード**: 読者が検索窓に入れそうな言葉で考えます。1 つの欄に関連する語をまとめて入れられるので（例: `時間管理 業務改善 効率化`）、「その他の候補」も使って 7 欄を埋めましょう。タイトルにすでに入っている語を繰り返す必要はありません
- **カテゴリー**: 本の内容にいちばん合うものを選びます。売れやすさだけで内容と関係ないカテゴリーを選ぶと、KDP のガイドラインに反します
- **表記をそろえる**: タイトル・著者名は、KDP の入力欄・EPUB（`book.yaml`）・表紙で同じ表記にします（チュートリアルの「[11. KDP に入力する情報を準備する](tutorial.md#11-kdp-に入力する情報を準備する)」も参照）
- **AI で書き直す場合**: KDP の登録画面で、文章を AI で生成したかどうかを正直に回答します
